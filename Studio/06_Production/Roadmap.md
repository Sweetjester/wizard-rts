- ~~A second and third win-objective type~~ — **first pass done 2026-08-23**. Boss-defeat was the only win path that existed. - ~~Wizard hero leveling with real player choice~~ — **first pass done 2026-08-23**, WC3-style. - ~~Map-discovered wizard upgrades~~ — **first pass done 2026-08-23**, WC3-style creep-camp item drops. Destroying an outpost or clearing a content plot now automatically grants the wizard a permanent relic upgrade. See Decisions Log.
- ~~Terrible Vault research depth~~ — **first pass done 2026-08-23**, WC3-style tiered upgrades. `hardened_horrors`/`thorned_vines`/`launcher_bile` are now 3-rank upgrades with escalating cost and effect (like WC3's Blacksmith weapon/armor tiers); `accelerated_evolution` stays single-rank. See Decisions Log.
- **Roguelike run structure** — design target: class selection [done], procedural map [done], randomized objective [3 of ~9 objective types now exist], map-discovered upgrades [first pass done], tower research [now has real depth via tiers, see above]. Still open, and the largest remaining piece: research/relics/leveling are still separate flat systems, not woven into a single "run-defining upgrade" experience the way §17's own examples describe (e.g. "skeletons explode on death" — a playstyle-changing unlock, not a numeric buff). That's a bigger design lift than an engineering pass.

## Army control / UX at scale

- ~~Control groups, tab-cycling, army-scale management~~ — **first pass done 2026-08-31**. This was the direct engineering consequence of the 2026-08-26 §5 correction ("hundreds of units, not dozens", held tactical by *control tooling* rather than APM): the input layer had no control groups and no cycling of any kind. Now has control groups 1-9 (assign/add/recall, double-tap to snap camera, auto-cleanup on death), F1 select-wizard, F2 select-army (deliberately excluding the wizard), F3/F4 idle-Barracks and idle-unit cycling, Tab/Shift+Tab type filtering (WC3 subgroup cycling, made non-lossy), and a Wizard-RTS-specific **reinforce group** that auto-absorbs newly trained units and walks them to the army's live position. See Decisions Log for the research, what was deliberately *not* ported, and the mass-LOD hole this work found and closed.
- **Army-wide stances** — not built, and it needs a design call first, not an engineering pass. §29 wants tactical depth without APM; "aggressive / defensive / hold ground" is the obvious RTS answer, but it interacts with the evolution system (does an evolved unit inherit its stance? does stance affect what it evolves into?) in ways that are a design question. Route to Andrew before anyone builds it.
- **Camera location hotkeys** (SC2/Stormgate `Ctrl+F1-F4`) — deliberately skipped for now; double-tap-to-snap on a control group covers the same need at this map size. Revisit if maps get bigger.
- **Queued / shift-chained orders** — not implemented. Genuinely modern, genuinely missing, and a natural next step for the same "fewer required actions" goal. Not attempted this pass to keep the change surface contained.
- **Control-group digits are not rebindable** — hard-bound to 1-9 with Ctrl/Shift/Alt, matching WC3/SC2/AoE4. Everything else routes through `KeybindManager` and shows up in the pause menu's Key Binds tab automatically.

## 3D map view (added 2026-08-31)

- ~~3D presentation of the normal game mode~~ -- **first pass done**. Enabled by a "3D map view" toggle on the map-select screen. The 2D simulation is untouched and authoritative; `Map3DView` renders the live map, mirrors units, owns a 3D camera, and bridges the mouse back into simulation coordinates. One scene, no fork. See Decisions Log.
- ~~Units render as capsules~~ -- **done 2026-09-02**. Units with 2D sprite art now render as billboarded `Sprite3D`s mirroring their own `ArtSprite` (same texture, same sheet grid, same frame), with a capsule fallback past a 220-sprite budget. No animation logic was duplicated. See Decisions Log.
- ~~The whole KoN roster rendered as capsules in 3D~~ -- **fixed 2026-09-03**, and not by commissioning art. Those units are not featureless in 2D: they draw detailed procedural art in `_draw()` (the Oaven has a teal body, cyan eyes, a red scarf and a spear), and the 3D view was throwing it away. Each art-less archetype is now rendered once into a `SubViewport` and billboarded, so 3D shows exactly what 2D shows. 17 of 17 units render as sprites, zero capsules. See Decisions Log for the simulation-pollution hazard this creates and how it is contained.
- ~~Terrain marks read as arbitrary orange scatter~~ -- **fixed 2026-09-03**. The 3D view was mirroring the 2D overlay's full blocker wash; in 3D rocks and trees are visible geometry, so marking them was noise. 3D now marks cliff edges only -- the one thing a top-down 3D view genuinely cannot convey, since a height change reads only as a change in shading.
- ~~Bio Absorber appeared unbuildable in 3D~~ -- **fixed 2026-09-03**. Not a placement bug: economy spaces are its only legal cells, `PlotRenderer` draws them, and this mode hides every `CanvasItem`, so the legal cells were simply invisible. They are now marked in cyan. See Decisions Log for the staleness trap underneath it.
- **KoN unit models: investigated 2026-09-02, blocked on source art.** Serpent, Spawner and The Forbidden have **no 3D model at all**; only the Oaven does, and rendering it produced a sheet with no readable silhouette -- worse than the procedural vector art already in game, so nothing was shipped. `blender_sprite.py` worked correctly and is not the constraint. See Decisions Log for the three Blender traps hit and why the render is unusable.
- **Only 4 units have sprite sheets** (`bad_kon_willow`, `terrible_thing`, `horror`, `apex`). This is still the section 37 art gap, but it is no longer a 3D-specific one: since 2026-09-03 the 3D view shows the same procedural art the 2D view does, so both presentations are now equally (un)finished rather than 3D being visibly worse.
- ~~Camera pan, build preview, drag-select~~ -- **fixed 2026-09-02** after Andrew found the mode unplayable. Camera now matches `CameraController` feature-for-feature (keyboard, edge pan, middle-drag, zoom, clamp); the build footprint renders as 3D pads; drag-select moved to screen space, which is the correct model under a perspective camera. See Decisions Log, including the process failure that let it ship broken.
- **Still missing from the 3D view**: unit health bars, selection rings, evolution/level chrome (all 2D `_draw()`), camera rotation, day/night, the mass-unit LOD system. Baked billboards are a single fixed east-facing frame -- units do not turn to face their movement, which is the most obvious remaining difference from 2D. Visual rather than functional, but they are the gap between "works" and "feels like the 2D game".
- **Vinewall drag-placement** shows a 3D footprint but has not been driven end-to-end.
- ~~2D sprites looked pasted onto the 3D ground~~ -- **fixed 2026-09-04, and it was the camera, not the art.** FOV was never set (Godot default 75), so the ground was seen from 14 to 89 degrees *within one frame* while every billboard presented the same face -- no art angle could match. Pitch was 52 while the art is drawn at about 38. Now 35 / -38, with camera distances authored in reference units so FOV changes perspective without reframing. `[ ] ; ' \ Bksp` tune both live in debug builds. See Decisions Log.
- **Prototype previewer still uses the old 52 degree pitch** (`map_3d_renderer.gd`, standalone mode only -- the embedded path is unaffected). Art evaluated in the previewer will not match how it looks in game. Worth aligning before it is used for another art-direction call.
- **Orthographic camera** -- not done, and the logical next step if the narrowed FOV is not enough. It would cut the cross-frame angle spread to *zero*, which is the guarantee pre-drawn 2D art actually wants, and is what most 2D-art strategy games use. Costs: zoom becomes a size change rather than a distance change, and perspective stops working as a depth cue. Ground projection maths would still work.
- **3D asset direction** -- the 128 terrain props read as far more natural than the 2D billboards, which prompted a review on 2026-09-04. Conclusion: the sample is biased (everything that looks natural is *static scenery*; everything that looks wrong *moves*), and the recommendation is a hybrid -- buildings are the strongest 3D candidate (7 of them, static, currently zero 3D models), units stay 2D but should be re-sourced from 3D renders at the now-fixed camera angle, the way AoE2/StarCraft/Diablo 2 did. Needs an Andrew decision; see Decisions Log.
- **Needs an Andrew decision**: this touches the 2026-08-08 "staying 2D" decision. Nothing is reversed -- 2D is still the default and the only mode with real art -- but whether the 3D view grows beyond a viewer is a design call about where art effort goes.
- **Performance is unmeasured at scale.** Unit mirroring is throttled to 20Hz into a MultiMesh, but it has not been run against the stress suite. Do that before treating the mode as playable at the hundreds-of-units target.

## Fog of war and pacing (2026-09-02)

- ~~Fog of war~~ -- **re-enabled on the live map** and rebuilt around a shared one-texel-per-cell vision texture sampled by both the 2D overlay and a 3D fog plane. Soft edges come free from linear filtering; the old per-cell drawing was both the blockiness and the cost that got it switched off. See Decisions Log.
- ~~3-minute grace period before wave 1~~ -- **done**, in both presentations. Phases, waves and the boss are measured from the end of grace, so their spacing is unchanged.
- ~~Fog cost 63ms per update~~ -- **fixed 2026-09-02**, now 4ms average / 6.25ms worst. Per-cell array allocation in the line-of-sight check, per-unit reveals, two full-map loops per update, and per-unit reflection. A full vision pass is now amortised across updates. See Decisions Log.
- ~~Enemies spawned during the grace period~~ -- **fixed**. Outposts spawn defenders on their own timer and were not gated by the wave director.
- ~~Mouse panning felt wrong in 3D~~ -- **fixed**. Now true 1:1 ground-under-cursor dragging instead of a fixed pixels-to-world factor, which cannot be correct under a perspective camera.
- **Fog changes how the map plays**, not just how it looks -- enemies are concealed until scouted. Worth a play before treating it as settled; the day/night pass in August deliberately avoided re-enabling it for this reason.
- ~~Buildings had no line of sight~~ -- **fixed 2026-09-02**, structures are fog revealers with authored sight radii.
- ~~Units could see and shoot up cliffs~~ -- **fixed**. Sight travels level or downhill only; engaging a higher target needs line of sight or a nearby ally spotting. Applies to the enemy AI by construction, since it lives in the shared combat tick.
- ~~No way to read impassable terrain in 2D~~ -- **fixed**. Cliff edges marked bright orange, blockers a dim wash, baked once into a texture and masked by fog so it never reveals unscouted ground.
- ~~Structures rendered as boxes and ignored fog in 3D~~ -- **fixed 2026-09-02**. Buildings billboard their real `art_sprite`, sized from the 2D art scale, and are fog-gated like units. The missing reveal check on structures was the visible "LOS is broken" symptom.
- ~~3D camera panning felt rough~~ -- **fixed**. Cost was measured first and was not the cause (0.33ms/sync); the focus was being written directly by each input, so it moved in per-event jumps. Now eases toward a target, frame-rate independently, with 1:1 drag exempt.
- ~~The 3D view does not draw the impassable overlay~~ -- **done 2026-09-02**. Per-cell MultiMesh quads sitting on each cell's own surface height, so plateaus do not bury them. See Decisions Log.
- **High-ground cliff lips are not marked**, in either mode -- `_is_unramped_height_edge()` excludes plot interiors so a base does not paint itself orange, and most high ground is base plots. The low-side lip is marked instead, which is the side the player approaches. Worth a design look if the high side should read too.
- **Previously: the 3D view did not draw the impassable overlay** -- cliffs are legible there from the geometry, but the marker should be added for consistency.
- **Fog does not yet affect the minimap**, and structures are not concealed (only units).

## Performance

- ~~In-game freezes~~ — **fixed 2026-08-31**. Andrew reported repeated freezes; his telemetry export pinned it to a single flow-field rebuild costing **~1270ms**, triggered every time a building or Vinewall was placed. Now **79ms**. Root causes were an O(n)-insert Dijkstra frontier, per-call recomputation of terrain traversability, and caches being thrown away on every blocker change. See Decisions Log — including a float32 precision trap that made an early version look 2x faster while silently halving the reachable map.
- **Sustained cost above ~40 units** — **open, and the next performance item**. The same telemetry, with the freeze frames excluded, shows `process_ms` crossing the 60fps frame budget at 40-59 units (10.4ms → 27.4ms) and `combat_tick_ms` jumping 20x (0.9ms → 18.6ms) for a 1.7x increase in units. That step change is not a scaling curve and needs its own investigation. Path requests also reach 370-540/second at 70-90 units — roughly 5-6 repaths per unit per second. **This matters disproportionately given §5's target of hundreds of units**: the game is currently over budget at fifty. Deliberately not rushed into the freeze-fix pass.
- **Cost regressions are now testable** — `flow_field_cost_smoke_test.gd` is the first test in the suite that asserts on *time*, not just correctness, closing the gap the 2026-08-23 entry flagged and left open. Worth copying the pattern for the combat tick above. `scripts/tools/flow_field_bench.gd` is the matching profiling tool.

## Stat system

- ~~Evolution wiped researched upgrades~~ / ~~upgrades keyed on archetype not family~~ / ~~unit cards understated every evolved form~~ -- **all fixed 2026-08-31**. See Decisions Log; found by explaining the cards, not by a test.
- **`WeaponCatalog` damage numbers are dead data** -- `get_weapon()` overwrites `damage` and `speed` from `UnitCatalog`, so the values in `weapon_catalog.gd` never apply. `kind`/`color`/`casts`/`aoe_radius` there *are* live. Worth either deleting the dead keys or adding a comment at the top of that file so nobody tunes them expecting an effect.
- **Magic armor is near-inert** -- only poison damage-over-time is tagged magic; everything else is physical. Every unit carries a `magic_armor` stat that currently does almost nothing. Needs a design call: either give more attacks a magic damage type, or drop the stat.
- **Four progression systems still stack flat numbers** -- evolution, tower research, wizard leveling, relics. Unchanged from the 2026-08-23 assessment; s17 wants playstyle-changing unlocks instead. Now slightly more urgent, since this pass showed the systems do not even compose correctly without explicit reconciliation.

## Art

- **Artwork pipeline flagged as needing structural rework** — see `MASTER_DESIGN_DOC.md` §37 (2026-08-19). Two disconnected generation pipelines exist (3D/Meshy, was feeding a non-shipping preview scene; 2D/PixelLab, has actually shipped real assets but let a fully-generated batch sit unreviewed for ~4 months). **Animation is the single largest gap** — only one unit (Oaven Spear) has ever been bridged from any pipeline into real working 2D gameplay animation; everything else is placeholder motion. Don't generate more static art volume before this is addressed.
- ~~Build the actual 2D pipeline / decide what to do with the 3D investment~~ — **partially resolved 2026-08-19**. The real 2D terrain-paint + prop-sprite system in `map_generator.gd` was found already built (just pointed at placeholder "Tiny Swords" art); wired in salvaged PixelLab art + this session's tree sprites with zero new config, verified live (212 trees/710 rocks rendering in the actual shipping scene). The 3D/Meshy investment: still not formally archived-vs-kept decided, but §37 recommends 2D/PixelLab as the default going forward for new gameplay art.
- ~~Full-coverage pass on `DARK_FOREST_FRONTIER_V2`~~ — **done 2026-08-16 to 08-19** (see Decisions Log). Went from ~10 of 30+ categories touched to nearly full coverage, including a new `LANTERN_TREE_BLOCKER` category. This was all built for `map_3d_renderer.gd` (the non-shipping preview scene) before the architecture finding above — the assets themselves may still be worth salvaging into the real 2D pipeline the way the tree billboards were, but that hasn't been done category-by-category yet.
- Ground/road/water tiles in the real 2D game are still Tiny Swords placeholder colors — highest remaining visual-impact item, blocked on a `PIXELLAB_API_KEY` that isn't set anywhere (`.env` or shell). A new square-tile manifest is drafted and ready to submit the moment the key exists.
- Five prop types from the abandoned PixelLab batch were never generated (giant mushroom, ruin floor, wizard tower wall, bandit wall, economy plot) — already `enabled: true` in `tools/pixellab_terrain_asset_manifest.json`, just needs the key to run.
- High-ground tier (`HIGH_GROUND_TILE`, glass-mushroom palette per the Art Bible) — still not built; still just a tinted low-ground texture. Unchanged from 2026-08-11.
- Environmental animation (wind-sway trees, glow-pulse on emissive materials) — still documented intent only, not implemented. Now subsumed into the broader animation gap logged in §37 above.

- ~~Day/Night cycle~~ — **first pass done 2026-08-23**, §25. Was fully absent. Now a real, tested effect: Day boosts economy income (+15%) and biases outposts toward weaker defenders (2/3), Night does the opposite (-15% income, 55% heavy defenders) — deliberately doesn't touch wave-spawn cadence (already tuned/perf-tested) or fog of war (intentionally disabled on this map type). See Decisions Log.
